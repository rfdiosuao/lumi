```python
"""Auth and license middleware."""
from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request
from starlette.responses import JSONResponse
from fastapi import Response

PROTECTED_PATHS = {"/api/process/start", "/api/image/generate", "/api/video/generate"}

class TokenAuthMiddleware(BaseHTTPMiddleware):
    def __init__(self, app, token: str):
        super().__init__(app)
        self.token = token

    async def dispatch(self, request: Request, call_next):
        if request.url.path.startswith("/docs") or request.url.path.startswith("/openapi"):
            return await call_next(request)
        req_token = request.headers.get("X-Bridge-Token")
        if req_token != self.token:
            return JSONResponse(status_code=401, content={"error": "未授权的请求"})
        return await call_next(request)

class LicenseGuardMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        if request.url.path in PROTECTED_PATHS:
            from api.deps import get_license_mgr
            if not get_license_mgr().is_authorized():
                return JSONResponse(status_code=403, content={"error": "需要有效的许可证"})
        return await call_next(request)
```

```python
"""Image generation endpoints."""
import base64
import os
import tempfile
from fastapi import APIRouter, HTTPException
from api.deps import get_image_client, append_log
from api.models import ImageGenerateRequest
from services.image_api import ImageApiError

router = APIRouter()

@router.post("/generate")
async def generate_image(req: ImageGenerateRequest):
    client = get_image_client()
    temp_file = None
    edit_path = req.editImagePath

    if edit_path and edit_path.startswith("data:"):
        try:
            header, b64_data = edit_path.split(",", 1)
            mime_type = header.split(":")[1].split(";")[0]
            image_bytes = base64.b64decode(b64_data)
            ext = mime_type.split("/")[-1].split("+")[0]
            if ext not in ("png", "jpeg", "jpg", "webp"):
                ext = "png"
            fd, temp_file = tempfile.mkstemp(suffix=f".{ext}")
            with os.fdopen(fd, "wb") as f:
                f.write(image_bytes)
            edit_path = temp_file
        except Exception as e:
            raise HTTPException(status_code=400, detail=f"图片数据解码失败: {e}")

    try:
        results = client.generate_many(
            req.baseUrl, req.apiKey, req.prompt, req.size,
            count=req.count, edit_image_path=edit_path
        )
        images_b64 = [base64.b64encode(r).decode() for r in results]
        return {"images": images_b64, "count": len(images_b64)}
    except ImageApiError as e:
        raise HTTPException(status_code=500, detail=str(e))
    finally:
        if temp_file and os.path.exists(temp_file):
            try: os.unlink(temp_file)
            except OSError: pass
```

## 2. 重构二：消除假包机制

### 2.1 问题详述

当前 [bridge.py L24-L42](file:///d:/Axiangmu/AUSTART/openclaw_new_launcher/python/bridge.py#L24-L42) 使用运行时动态创建 `sys.modules` 条目的方式，让旧的 `from openclaw_launcher.xxx import ...` 导入路径在新目录结构中工作：

## 3. 重构三：Rust 层定位明确化

### 3.1 问题详述

当前 Rust 层（[lib.rs](file:///d:/Axiangmu/AUSTART/openclaw_new_launcher/src-tauri/src/lib.rs)）只有 3 个 command，全部是"壳"逻辑：
- `get_bridge_port` — 读全局变量
- `start_bridge` — 启动 Python 子进程
- `proxy_request` — HTTP 转发

**核心矛盾**：Tauri 选 Rust 的意义在于性能和安全，但当前 Rust 只做了 Python 的"启动器+代理"，没承担任何业务职责。

### 3.2 方案：Rust 承担安全敏感 + 系统级职责

**原则**：不把所有 Python 逻辑搬到 Rust（成本太高），只把**安全敏感**和**系统级**逻辑迁移。

#### 3.2.1 立即做：授权验证搬到 Rust

**原因**：`license_manager.py` 用 Ed25519 验签，但 Python 源码可被用户直接修改绕过。编译后的 Rust 二进制几乎不可篡改。

**新增 Rust command**：

```rust
use ed25519_dalek::{VerifyingKey, Signature, Verifier};
```

## 4. 重构四：通信链路简化

### 4.1 问题详述

当前调用链：

```
React → invoke('proxy_request') → Rust reqwest → HTTP → Python Handler → 返回
```

每次 API 调用经历 4 层序列化/反序列化，Rust 层只是无脑转发。

### 4.2 方案A：前端直接 fetch Python（推荐）

**思路**：Rust 只负责启动 Python 进程和告知前端端口号，前端直接用 `fetch` 访问 Python API。

```
React → fetch('http://127.0.0.1:{port}/api/xxx') → Python FastAPI → 返回
```

**优势**：
- 减少一层 IPC 序列化/反序列化
- Rust 不再是性能瓶颈
- 前端可直接使用 `ReadableStream` 支持 SSE（视频生成进度）

**实现**：

修改 [api.ts](file:///d:/Axiangmu/AUSTART/openclaw_new_launcher/src/services/api.ts)：

```typescript
let bridgePort = 0;
let bridgeToken = "";

export async function initBridge() {
    const { invoke } = await import('@tauri-apps/api/core');
    bridgePort = await invoke<number>('get_bridge_port');
    bridgeToken = ""; // Token 通过 Rust command 获取，或首次请求时获取
}

async function api<T>(path: string, method: string = 'GET', body?: Record<string, unknown>): Promise<T> {
    const url = `http://127.0.0.1:${bridgePort}${path}`;
    const headers: Record<string, string> = {
        'Content-Type': 'application/json',
    };
    if (bridgeToken) headers['X-Bridge-Token'] = bridgeToken;

    const resp = await fetch(url, {
        method,
        headers,
        body: body ? JSON.stringify(body) : undefined,
    });

    const data = await resp.json();
    if (!resp.ok || data.error) {
        throw { error: data.error || `HTTP ${resp.status}` };
    }
    return data as T;
}
```

**Rust 侧简化**：删除 `proxy_request` command，只保留 `get_bridge_port` + `start_bridge` + 新增 `get_bridge_token`。

**Tauri CSP 配置**（tauri.conf.json）：

```json
{
  "security": {
    "csp": "connect-src 'self' http://127.0.0.1:* http://localhost:*"
  }
}
```

### 4.3 方案B：保留 Rust 代理但增强

如果出于安全考虑（不想暴露 Python HTTP 端口给其他进程），可保留 `proxy_request`，但增加：
- 请求超时控制
- 重试机制
- 响应流式传输（SSE）

## 8. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| FastAPI 依赖需要预装 | 打包体积增大 | 使用 `pip install -t` 将依赖打包到 python/ 目录 |
| 前端直接 fetch 可能暴露端口 | 其他进程可访问 API | Token 认证已保护；生产环境可监听 127.0.0.1 |
| Rust 授权验证迁移 | 需要重新实现 Ed25519 验签逻辑 | `ed25519-dalek` crate 与 Python `cryptography` 兼容 |
| 迁移期间功能回归 | 可能引入 bug | 逐端点迁移，每个端点独立测试 |
| Python 依赖版本冲突 | 用户环境可能不兼容 | 考虑内嵌 Python（embeddable package） |

---

> **总结**：你的架构方向没有错，Tauri + React + Python Sidecar 是合理的技术组合。问题在于"迁移不彻底"——旧代码的残留（假包、手写HTTP路由）和"新层没做实"（Rust 只做了空壳）。按此方案分阶段重构后，每一层的职责将变得清晰：**Rust 管安全与系统、Python 管 AI 与业务、React 管 UI**，不再是"四不像"，而是各司其职。
